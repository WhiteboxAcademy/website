What Python already knows

Build it

Turn a function into a Tool

Open whitebox/tools.py, the new file in this chapter. json_type translates Python types into JSON Schema’s words. For list[float], get_origin gives list and get_args gives (float,). Then parameters_of uses everything from peek.py:

def parameters_of(function):
    """Build the parameters schema from the function's signature."""
    hints = get_type_hints(function, include_extras=True)
    properties, required = {}, []
    for name, parameter in inspect.signature(function).parameters.items():
        hint = hints.get(name)
        if get_origin(hint) is not Annotated:
            raise ValueError(f'{function.__name__}: write {name} as Annotated[type, "description"]')
        kind, description = get_args(hint)
        properties[name] = {**json_type(kind), "description": description}
        if parameter.default is inspect.Parameter.empty:
            required.append(name)
    return {"type": "object", "properties": properties, "required": required}

{**json_type(kind), "description": description} builds a new dictionary: ** copies in everything from the first one. The raise is on purpose, and you’ll test why below.

In chapter 04, you wrote a decorator that stored a function. This one gives back a Tool:

@dataclass
class Tool:
    name: str
    description: str
    parameters: dict
    function: Callable

    def __call__(self, *args, **kwargs):
        return self.function(*args, **kwargs)


def tool(function):
    """Turn a function into a Tool."""
    if not function.__doc__:
        raise ValueError(f"{function.__name__}: a tool needs a docstring")
    return Tool(function.__name__, inspect.getdoc(function), parameters_of(function), function)

Callable is the type hint for “something you can call”. __call__ is a special method, like __init__. It runs when you use an object as a function, so a decorated tool can still be called. inspect.getdoc reads the docstring and tidies its indentation.

Why it’s strict

Build it

The Toolbox

A Toolbox holds an agent’s tools, and it’s the only thing that runs them. run is chapter 12’s run_tool, plus a check of the arguments against the schema:

    def check(self, tool, arguments):
        """Return what's wrong with these arguments, or None."""
        parameters = tool.parameters
        missing = [name for name in parameters["required"] if name not in arguments]
        unknown = [name for name in arguments if name not in parameters["properties"]]
        if missing:
            return f"Error: {tool.name} needs {', '.join(missing)}"
        if unknown:
            return f"Error: {tool.name} doesn't take {', '.join(unknown)}"
        return None
    def run(self, call):
        """Run one tool call. Errors go back to the model as text so it can recover."""
        tool = self.tools.get(call.name)
        if tool is None:
            return f"Error: there is no tool called {call.name}. You have: {', '.join(self.tools)}"
        problem = self.check(tool, call.arguments)
        if problem:
            return problem
        try:
            return str(tool(**call.arguments))
        except Exception as error:
            return f"Error: {error}"

Common mistakes

  • Writing a vague description. Annotated[str, "A path"] passes the check, but it doesn’t help. Show the model an example.
  • Forgetting @tool. A plain function has no .name, so Toolbox fails when you create it.
  • Writing poor error messages in a tool. Toolbox.run turns them into text, and the model has to read them.
  • Thinking a check means it’s safe. check only compares names, and read_file can still read any path it’s given. Chapter 30 deals with that.
Recap

What you opened

  • A tool written twice can disagree with itself, and neither Python nor the model warns you.
  • A function already holds most of its schema: its name, type hints, defaults and docstring.
  • Annotated adds the one thing missing, a description for each parameter.
  • @tool builds a Tool from the function, so there’s only one thing to keep up to date.
  • Toolbox checks each call against the schema and sends every failure back as text.

Annotated is described in the typing documentation, and the schema format is JSON Schema.
