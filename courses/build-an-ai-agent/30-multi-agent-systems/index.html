Multi-agent systems

Is a team of agents better than one? Build one, then test it on six kinds of job, and see where it wins, where it loses, and how to choose.

Get this chapter’s code
Where we are

The next step, or so people say

Part 6 ended with an agent that can use tools it doesn’t own. The usual next step is to split the work between several agents. Sometimes that’s right. Often it isn’t. This chapter teaches one new idea, an agent can be a tool for another agent, then tests it on six kinds of job.

By the end, you should be able to look at a job and choose an architecture, with a reason.

Start Ollama, activate the .venv from chapter 05, and work in chapters/30-multi-agent-systems/code. The number to beat: one agent with one search scored 113 of 126 on chapter 29’s eval.

The one idea

An agent as a tool

A Tool is a name, a description, some parameters and a function. Nothing says that function can’t run a whole agent.

def agent_tool(agent, name, description):
    """Turn an agent into a tool. Each task starts a fresh chat, so the task must say everything."""

    def ask(task: Annotated[str, "The whole task, with every detail from the user"]) -> str:
        return agent.run(task).answer

    return Tool(name, description, parameters_of(ask), ask)

The worker starts with an empty chat, so it knows only what the task says. The manager sees only the answer. Predict: how many model calls does one question take now?

$ python3 first_team.py

It worked, in four model calls. One agent takes two.

A cheaper team

A router

One model call picks a worker, and that worker does the whole job.

    def pick(self, question):
        names = "\n".join(f"{name}: {description}" for name, (description, _) in self.workers.items())
        prompt = f"Who should handle this request?\n{names}\n\nRequest: {question}\n\nReply with only the name."
        said = self.model.chat([Message("user", prompt)], temperature=0).content.lower()
        return next((name for name in self.workers if name in said), next(iter(self.workers)))

Predict: four questions, two for each worker. How many arrive at the right one?

The first test

Does the team beat one agent?

Predict: specialists have smaller, cleaner indexes. Will they beat 113?

$ python3 read_results.py teams
Setup                  Of 126  Calls  Tokens in  Seconds
one agent                 113    260    111,692      400
two tools                  88    287    163,105      555
router                     96    384    116,254      425
router, new wording        94    392    135,943      422
manager                    92    499    191,316      692

Every real team did worse, and cost more. Splitting the documents created a decision, and that decision can go wrong. Rewording the router only moved the mistakes around: wrong routes went from 18 to 33.

The perfect router was told the right worker every time, and it only tied at 113. So a better router can only catch up here.

We expected details to get lost in handoffs, and they didn’t. The manager passed 114 of 126 tasks on word for word.

A team also multiplies limits: 8 steps inside 8 steps can mean more than 60 model calls.

When it breaks

What published work says

Where a team should win

  • Too big for one context, and it splits cleanly. Chain of Agents beat retrieval on all eight datasets it was tested on.
  • Independent pieces. A Google, DeepMind and MIT study found +80.8% on finance work that splits, and up to −70% on sequential planning.
  • Other reasons. Different permissions, or another company owns part of it.

The warning: many wins may just be extra compute. At equal budget, single agents matched or beat teams in two studies, one on a 7B model. So every test here has a fair rival.

Test two

More agents, or more steps?

Hop questions need two facts. Its rival is one agent told to do the same two steps. Predict: which comes out on top?

$ python3 read_results.py relay
Setup                 Five passes, of 30  Of 150  Calls per pass
one agent             11 11 11 10 10          53              61
relay of two agents   17 20 18 18 20          93             117
one agent, two steps  17 15 16 14 13          75              98

Two steps took one agent from 53 to 75, so extra work is part of the gain. The relay did better again, at 93, using about a fifth more calls.

The relay’s two agents are the same model with the same prompt. The real differences are a clean chat and how the note is worded, so this may say more about clean context than teamwork. We didn’t test which part did it.

After one pass they tied at 17, and we wrote that the agent added nothing. Five passes said otherwise. One pass wasn’t enough to say.

Too big for any window

  • Search can’t count what it can’t see.
  • 48 small workers got closest: 3% to 16% on late deliveries, and 21% to 46% on the others.
  • A team of 4 was erratic. The pieces had to be small.
  • Plain text search got run-outs exactly right, with no model at all.

Our first count seemed to collapse, finding 7 run-outs of 166. The workers were right, and our check was case-sensitive. When a result looks too bad, suspect your test.

The point

Choosing an architecture

  1. Can plain code do it? Use code.
  2. Do parts need different permissions, or does someone else own them? Split for that reason.
  3. Does it fit in one call, or a bigger window? One agent. For more thinking, add steps first.
  4. Does it split into small, independent pieces? A team of small workers, and code joins the results.
  5. None of those? Rethink the job.

Then measure your choice against the simpler option at the same budget, and keep the team only if it wins.

Recap

What you opened

  • An agent can be a tool for another agent, and Agent didn’t change.
  • One agent scored 113 of 126. Real teams scored 92 to 102, and a perfect router only tied.
  • On dependent steps, a relay got 93 of 150, one agent with two steps 75, and one agent 53.
  • A fresh reviewer fixed 5 and broke 5.
  • Past the window, one chat scored zero. One chat each got 93 of 108, and a bigger window got 83 in far fewer calls.
  • On a job too big for any window, small workers came closest, and were still 3% to 46% off.
  • Plain text search counted run-outs exactly.

Start with one agent. Split only when you can name what forced you to, and then measure it.
