Walkthrough

Building up a model call

  1. The chat function

    A model call is an HTTP request, like the ones in chapter 05. body holds the model, the conversation and your settings. raise_for_status stops with an error if something failed, and the reply text is at ["message"]["content"]. You’ll use this function for the rest of the course.

  2. Your first question

    You send a list of messages. This is the list of dictionaries from chapter 02. Each message has a role, and this one comes from the user.

  3. System messages

    A system message sets the rules, and it comes from you, the developer. Be specific. Our first attempt, “You are a pirate”, gave a plain answer with no pirate voice at all.

  4. Conversations

    To continue a conversation, send all of it, including the model’s earlier assistant replies. The word “it” only makes sense because the earlier messages are included.

  5. Streaming

    Streaming gives you a reply piece by piece as it’s written. Ollama sends one line of JSON for each piece, and a generator from chapter 04 yields them.

Two puzzles

Predict before you run

You now have a working model call, but two things may surprise you. Before you run this part, make a guess:

  1. If you ask for a cat name three times, will you get the same answer?
  2. If you tell the model your name, then ask for it in a second call, will it remember?

Why does the same question give different answers? Why did it forget your name? You’ll find out in the next chapter.

Your turn

Exercises

Open exercises.py and complete the five TODOs. Together, they build the pieces of a model call:

  1. user_message: build a message.
  2. with_system: add a system message.
  3. build_body: build the request body.
  4. reply_text: read the reply.
  5. join_stream: join streamed pieces.

Then run python3 -m pytest test_exercises.py. You’ve finished when you see 5 passed.

Common mistakes

  • Sending a single dictionary instead of a list of messages.
  • Writing vague system messages. Be specific about what you want.
  • Forgetting stream=True in both the body and requests.post when streaming.
  • Expecting the same answer every time.
