Classes, dataclasses and type hints

Give your data structure and behavior, using the same shapes your agent framework will be built from.

Get this chapter’s code
Where we are

Dictionaries only go so far

In chapter 02, you stored data in lists and dictionaries. A dictionary can’t stop you misspelling a key, and it can’t carry its own behavior. Classes solve both.

You’ll use these ideas throughout the framework. Message and Conversation hold an agent’s history, type hints describe its tools, and a shared base class lets you swap one model for another. Open chapters/03-classes-type-hints/code/models.py and follow along.

Walkthrough

From a blueprint to a shared shape

  1. Classes

    A class is a blueprint that groups data with the functions that use it. __init__ sets up each new object, and self means “this object”. A value stored on the object is an attribute, and a function in the class is a method.

  2. Dataclasses

    A dataclass writes __init__ for you, and gives you readable printing and == comparison. A list field needs field(default_factory=list), so each object gets its own list.

  3. Inheritance

    A base class defines a shape, and each subclass fills in the details. Code that uses a Tool doesn’t care which one it gets. In chapter 13, this same idea makes your model replaceable.

Type hints

Type hints describe what a function takes and returns.

HintMeaning
text: strtext should be a string
limit: int = 10limit should be a whole number, and defaults to 10
-> strThe function returns a string
-> NoneThe function returns nothing
Message | NoneEither a Message or None
list[Message]A list of Message objects

Python doesn’t enforce type hints. They help people and tools read your code. Your program can also read them as data, and in chapter 14 you’ll use that to describe tools to a model automatically.

Four errors you’ll meet

These are real error messages:

What you didWhat Python saysThe fix
Forgot self in a methodTypeError: Order.total() takes 0 positional arguments but 1 was givenAdd self as the first parameter
Left out a valueTypeError: Order.__init__() missing 1 required positional argument: 'price'Pass the value in
Wrote price = priceAttributeError: 'Order' object has no attribute 'price'Use self.price = price
Used [] as a dataclass defaultValueError: mutable default <class 'list'> for field messages is not allowed: use default_factoryUse field(default_factory=list)

Common mistakes

  • Forgetting self in a method, or forgetting self. when you store a value.
  • Writing Order when you mean Order(). The brackets create the object.
  • Using [] as a default instead of field(default_factory=list).
  • Expecting type hints to stop wrong values. They don’t.
